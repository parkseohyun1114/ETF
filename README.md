# 🚨 ETF 괴리율 경보기

ENG3510 인공지능을 위한 데이터 분석 · 기말 프로젝트

상장 ETF 약 1,190개 전체를 매일 훑어서 **괴리율이 평소보다 유난히 튄 종목(Z > 2)** 을 띄우고,
종목을 누르면 **과거 같은 상황 이후 1·5·20거래일 동안 괴리율이 얼마나 되돌아왔는지** 보여주는 웹앱입니다.

## 문제

ETF는 시장가격(종가)과 실제 가치(NAV)가 어긋날 수 있고, 이 차이가 **괴리율**입니다.
괴리율이 크게 벌어진 날 매수하면, 나중에 괴리가 해소되면서 NAV보다 덜 오르는(혹은 더 떨어지는) 손해를 봅니다.
2026-11-18 기준 괴리율 1%를 넘는 ETF는 147개(약 12%)였고 해외·레버리지·원자재 ETF에 몰려 있었습니다.
개인 투자자가 "오늘 사면 위험한 ETF"를 바로 알 수 있도록 경보기를 만들었습니다.

## 판정 기준

| 항목 | 정의 |
|---|---|
| 괴리율 d | (종가 − NAV) / NAV × 100 |
| Z | (오늘 d − 직전 20거래일 d 평균) ÷ 직전 20거래일 d 표준편차 (오늘 값은 기준에 넣지 않음) |
| 위험일 | Z > 2 이고 d > 0 |
| 회귀 분석 | 위험일 뒤 1·5·20거래일의 괴리율 변화, 시장가 수익률 − NAV 수익률, 평소 날과 Welch t-검정 |

## 화면

1. **오늘의 경보**: 한 줄 결론과 주의 ETF 카드(과거 1년 같은 상황 뒤 회복률), NAV 하락형 '확인 필요' 목록, 유난히 싸게 거래된 할인일 ETF(Z < −2), 전체 괴리율 분포
2. **종목 분석**: 종목코드·이름 검색 또는 경보 표에서 클릭 → 기간(기본 최근 1년) 괴리율 추이, 경보선, 위험일 표시, 위험일 뒤 평균 경로, 1·5·20일 회귀 분석표
3. **검증**: KRX 공시값 대조, 결과보고서 위험일 수 재현, 데이터 정제 내역

## 실행

```bash
pip install -r requirements.txt
# 인증키: 아래 셋 중 하나 (저장소에는 절대 올리지 않음)
#   1) .streamlit/secrets.toml 에 KRX_API_KEY = "..."   (secrets.toml.example 참고)
#   2) 환경변수 KRX_API_KEY
#   3) app.py 옆 .krx_api_key 파일
streamlit run app.py
```

- 실행할 때마다 저장된 데이터(`data/etf_daily.parquet`, 2025-09-01부터) 뒤로 빠진 거래일만 KRX에서 받아 붙입니다.
- **오프라인 백업 모드**: 사이드바 토글을 켜거나 주소 끝에 `?offline=1` 을 붙이면 KRX에 접속하지 않고 저장된 데이터로만 돌아갑니다. 인증키가 없거나 KRX 호출이 실패해도 자동으로 저장된 데이터로 실행합니다.
- Streamlit Community Cloud 배포 시 앱 설정의 Secrets 에 `KRX_API_KEY = "..."` 를 넣습니다.

## 데이터 출처

KRX 정보데이터시스템(data.krx.co.kr)은 비로그인 요청에 `LOGOUT` 응답을 주어 pykrx 등으로 수집할 수 없었습니다.
그래서 **KRX 공식 Open API(openapi.krx.co.kr) · ETF 일별매매정보**(`etp/etf_bydd_trd`)를 사용합니다. 하루 1번 호출로 그날 전체 ETF를 받습니다.

## 검증

- **KRX 공시값 대조**: 이 API에는 괴리율 필드가 없어서, 같은 응답의 공시 필드(등락률, 시가총액, 고가·저가)를 앱이 원자료로 다시 계산해 대조합니다. 2026-11-24 거래가 있는 1,184개 ETF 모두 3개 항목 100% 일치.
- **보고서 재현**: 보고서 방식(2025-11-04~2026-11-03, 244거래일)으로 위험일 수를 다시 세면 2차전지 10 · 반도체 8 · 방산 9로 보고서와 일치.

## 개선 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| 위험일 수가 보고서와 달랐음 | KRX API가 휴장일에도 종가·NAV가 빈 행을 돌려줘 20일 기준선이 밀림 | 종가·NAV 결측 행 제거 → 10·8·9 재현 |
| 방산 ETF를 이름으로 찾으면 기간이 끊김 | 종목명이 "KODEX 방산TOP10레버리지" → "KODEX K방산TOP10레버리지"로 바뀜 | 이름 대신 종목코드(0100K0)로 필터 |
| 괴리율 상위에 17,000%대 종목 | ACE 러시아 등 거래정지 종목은 가격이 멈춰 괴리율이 비정상 | 거래량 0인 날은 판정 제외 |
| 경보가 너무 많음(Z만 기준) | 평소 괴리가 0에 가까운 종목은 0.1%만 벌어져도 Z>2 | 최소 괴리율 필터(기본 0.5%) 추가 |
| 발표장 네트워크 장애 위험 | 실행 때마다 KRX 호출 | 오프라인 백업 모드 추가 |
| 11/26 경보가 76개로 급증 | 채권·MMF·커버드콜 ETF에서 가격은 그대로인데 NAV만 하루에 1~5% 떨어짐(분배금 반영으로 추정) | 'NAV가 떨어져 생긴 괴리'를 가격이 튄 경보와 분리해 '확인 필요'로 표시 |
| 폰에서 읽기 어려움 | 넓은 표·작은 글씨·결론 없는 숫자 나열 | 첫 화면 결론 한 줄과 카드, 쉬운 표, 할인일 표, 가격제한폭 근처 극단일 ✕ 표시 |
| 화면 개편 뒤 재배포하자 KeyError('NAV주도') | Streamlit Cloud가 재배포 때 옛 형식 캐시를 그대로 씀 | 엔진 버전을 캐시 키에 넣고, 컬럼이 없으면 캐시를 비우고 다시 계산 |
| 배포 직후 앱이 UnicodeEncodeError로 멈춤 | Secrets에 예시 문구(한글)가 섞인 키가 들어가 HTTP 헤더에 넣지 못함 | 키를 미리 검사하고, KRX 호출이 어떤 이유로 실패해도 저장 데이터로 계속 실행 |

## 한계

- 위험일 뒤 괴리율이 줄어드는 것에는 극단값이 평균으로 돌아가는 통계적 현상(평균 회귀)도 섞여 있습니다. 평소 날과의 비교(Welch t-검정)로 일부 보정합니다.
- NAV는 장 마감 기준이고, 해외 ETF는 기초자산 시장 시간이 달라 괴리율이 구조적으로 클 수 있습니다.
- 데이터는 2025-09-01부터 보관합니다(종목 분석 기간은 그 뒤 약 1개월부터 선택 가능).
